# rhun extension protocol, version 1

Status: **v1, frozen on 2026-10-16** for rhun 0.18.0. Everything below is what rhun does; a
later rhun adds to the protocol only as v1.1 and later, announced by fields after `hello 1`
and by `RHUN_PROTOCOL`, and never changes what is written here. The canonical copy is
`v1/v1.md` in [rhun-editor/extension-protocol](https://github.com/rhun-editor/extension-protocol),
next to the line grammar `v1/v1.abnf` and the manifest schema `v1/v1.json`; rhun's repository
carries a copy at `docs/extensions/v1.md`.

An extension is a program. rhun starts it when it is needed, talks to it over its standard
input and output with one text line per message, and stops it when rhun quits. The program may
be written in any language. rhun never waits for it: everything the extension does is applied
when its reply arrives, and only if the document it refers to has not changed meanwhile.

## 1. Files

An installed extension is a folder `~/.config/rhun/extensions/OWNER/NAME/` (on Windows
`%APPDATA%\rhun\extensions\OWNER\NAME\`). `rhun --extensions DIR` uses `DIR` instead of the
folder, for development and tests. Inside:

| Path | Purpose |
| --- | --- |
| `extension.ini` | the manifest, required |
| the program | named by the manifest's `run.*` entries or `run` with `runtime` |
| `themes/*.theme`, `syntax/*.syn` | data files: themes join the list after the user's; grammars go after the user's and before the built-in ones, so an extension can refine a built-in language and the user still wins |
| anything else | the extension's own; the folder is read-only to the extension once installed |

The extension's writable folder is its **state folder**, `~/.local/state/rhun/extensions/OWNER--NAME/`
(`%LOCALAPPDATA%\rhun\extensions\OWNER--NAME\`), created before the first start. `HOME`,
`TMPDIR` and the common cache variables point into it (section 4).

## 2. Manifest

INI, UTF-8, `key = value`, `#` comments. Unknown keys are ignored. Required keys are marked.

```ini
name = format                    # required: [a-z0-9][a-z0-9-]*, equal to the folder name
owner = rhun-editor              # required: the GitHub owner, equal to the parent folder name
title = Format                   # required: shown in Settings and after command titles
version = 0.1.0                  # required
protocol = 1                     # required: the protocol version this extension speaks
run.linux-x86_64 = bin/format-linux-x86_64   # the program for that target, relative to the folder
run.macos-arm64 = bin/format-macos-arm64
run.windows-x64 = bin/format-windows-x64.exe
# or, for a script:
# runtime = python3              # a program found on PATH
# run = main.py                  # the script, passed as the runtime's first argument
# requires = python3 >= 3.10     # shown when the runtime is missing or too old (not checked by rhun 0.18.0)
args =                           # extra arguments, space separated, optional
on = command                     # when to start: startup | command | lang:LANG | open:GLOB | project
                                 # several, space separated; "command" is the default. Listing
                                 # other conditions replaces it, but invoking one of the manifest's
                                 # commands always starts the extension, whatever `on` says

[commands]
format_document = Format Document | ctrl+shift+i
# key = Title | default keys (space separated, as in [keys] of the config; "|" and keys optional)

[subscribe]
opened = *                       # which events to send, with name patterns: * for all, *.go a
saved = *.go *.json              # suffix, Makefile an exact name, matched against the file's name
changed = no                     # (not its folder), case-sensitively; the default is "no". A
                                 # document is reported at all only when `opened` names it; the
                                 # other keys select among those. An untitled document matches
                                 # only *. ready, active, closed (of a reported document), project,
                                 # run, resync and bye are always sent
cursor = no
selection = no
edits = *.go                     # every change as deltas (section 6a)
hover = *.go                     # the pointer resting on a position

[needs]                          # section 5
documents = write
project = read
home = none
network = no
terminal = no
run = gofmt rustfmt
```

A manifest that fails to parse, lacks a required key, has a `name` or `owner` other than its
folders' names, names no `run` entry for this target and no `runtime`, names a `runtime` that
is not on `PATH`, or a program that is missing or not executable, is recorded with its reason
and the extension is not started; Settings shows the reason. Commands are registered from the manifest
before the process exists, so the palette shows them and the keys work from startup.

Command names in the palette and in `[keys]` are `NAME.command`, for example
`format.format_document`; titles are shown as "Format Document (Format)". The user's `[keys]`
win over an extension's default keys, and a key a built-in command has stays with it; between
two extensions the one found first in the folder listing keeps a contested key (Settings >
Extensions shows the conflict). A command invoked while its program is still starting is
delivered after `ready` and the catch-up; a second one invoked before that replaces it.

### Activation

`on` lists conditions; the extension starts when any holds:

| Condition | Starts when |
| --- | --- |
| `startup` | rhun has drawn its first frame |
| `command` | one of its commands is invoked (default) |
| `lang:LANG` | a document whose grammar name is `LANG` is open or opened (names as `print-state` shows them) |
| `open:PATTERN` | a document whose file name matches the pattern (`*.ext` or an exact name) is open or opened |
| `project` | a project folder is open |

One process per extension; a start in progress absorbs further triggers.

## 3. Transport

Messages are lines of UTF-8 text ending in LF (CR before it is ignored), at most 65536 bytes.
Fields are separated by single spaces. The **last field of a message may contain spaces**:
it runs to the end of the line. A message whose last numeric field is a length `LEN` is
followed by a **body**: exactly `LEN` bytes after the LF, which may contain anything; the next
message starts at the byte after the body. Bodies are capped per message (section 7).

Three kinds of lines:

- **Requests**: `ID verb args…`, `ID` a decimal integer from 1 to 2147483647, unique among the
  sender's requests that have not been answered. Both sides send requests.
- **Replies**: `ok ID args…` or `error ID CODE text…`, in any order relative to other replies,
  always to a request the other side sent. A reply may carry a body, as `ok ID VERSION LEN`.
- **Events**: `0 name args…`, id 0, never answered.

Error codes: `syntax` (the line could not be parsed, or a request's arguments could not),
`unknown` (verb), `needs` (section 5; the text names the capability, as `needs
documents=write`), `nodoc` (no such document, or not a text document), `nofile` (`open`: no
such file), `readonly` (the document cannot be edited: a diff view), `stale` (the version is
not current; the text is the current version), `badpos` (a position is outside the document or
inside a multibyte character), `toobig` (more diagnostics, items or commands than the cap),
`busy` (a prompt is open, or the palette), `cancelled` (the user dismissed the prompt, or it
was closed), `refused` (a `cmd` not on the list of section 8a, a `register` of a name in use).
After a `syntax` error the message is dropped; three `syntax` errors in a row, with no
well-formed request between them, stop the extension. A line of 64 KB with no LF in it, or a
body over its cap, stops it at once: rhun does not read megabytes to discard them.

Requests are handled in the order they arrive and each is complete before the next is read,
except the prompts (`choose`, `ask`, `term`), which are answered when the user acts: `cancel`
of an open prompt closes it and answers it `cancelled`; `cancel` of anything else is `ok` and
does nothing.

An extension may answer a request from rhun at its leisure, or ignore events, but it must keep
reading: rhun's outgoing queue per extension is 1 MB, and an extension that leaves it full for
10 seconds is stopped.

## 4. Lifecycle

1. rhun creates the state folder, opens the log file
   `~/.local/state/rhun/extensions/OWNER--NAME.log` for the extension's standard error (cut back
   to empty when it passes 1 MB: the program keeps writing to it, so it cannot be rotated), and starts the program with its folder as the working directory
   and this environment and nothing else:

   | Variable | Value |
   | --- | --- |
   | `PATH` | rhun's own `PATH` |
   | `HOME` | the state folder |
   | `TMPDIR` | `STATE/tmp`, created |
   | `XDG_CACHE_HOME`, `GOCACHE`, `GOMODCACHE`, `GOPATH`, `npm_config_cache` | under the state folder |
   | `LANG`, `LC_ALL`, `TZ` | rhun's, when set |
   | `RHUN_VERSION` | rhun's version |
   | `RHUN_PROTOCOL` | `1` |
   | `RHUN_EXTENSION` | `OWNER/NAME` |
   | `RHUN_TARGET` | `linux-x86_64`, `macos-arm64` or `windows-x64` |
   | `RHUN_STATE` | the state folder |
   | `RHUN_PROJECT` | the project folder, or unset |
   | `RHUN_SOCKET` | the control socket path, only in a `--extensions DIR` session with `--control` |

   In a `--extensions DIR` session the extension also inherits rhun's own environment (tests
   pass their settings that way); an installed extension gets only the table above.

2. The extension writes `hello 1` (no id; further fields, if any, name capabilities of later
   protocol versions and are ignored by a rhun that does not know them) within **5 seconds**. Anything else first, or nothing, ends the process ("the
   first line was not hello 1", "no hello within 5 s"). A `hello` with another version:
   "protocol version not supported (rhun speaks 1)".
3. rhun answers with the event `0 ready PROJECT` (`-` without a project) and then **catch-up**,
   a snapshot taken between frames: `opened` for every open document the subscription matches,
   `active`, and `cursor`/`selection` for the active one when subscribed. The extension sees
   the same world as one started at launch.
4. Normal operation until rhun quits, the user stops the extension, or a limit trips.
5. Stop: rhun sends `0 bye`, waits 1 second, sends SIGTERM to the process group, waits 1
   second, SIGKILL. When rhun itself quits it sends `bye`, waits up to 300 ms for the programs
   to leave, and sends SIGTERM to the rest. (Windows: the job object ends the process.)
   Everything the extension registered at runtime (its commands, their keys), its marks, status
   text, per-document options and open prompt is removed. A program that closes its own input or output is stopped at once.
6. A process that exits on its own is "crashed" with its exit status; its manifest commands
   stay in the palette and invoking one starts it again. Three crashes within a minute leave
   it stopped: invoking a command then shows the reason, and only Settings restarts it. The
   same holds for every stop a limit caused. A failed start (no such file, permission) is "failed
   to start: reason".

If rhun dies, the extension dies: on Linux through the parent-death signal, on Windows through
the job object; on macOS the extension's standard input reaches end of file, and an extension
should exit when it does. The signal reaches the extension's own process, not programs it
started: an extension that runs a language server must stop it when its input ends.

A program that cannot be executed (a bad interpreter line, a binary for another system) is
"failed to start: the program could not be executed".

At most 16 extensions run at once; the seventeenth waits, idle, and starts when a slot frees.

## 5. Capabilities: `[needs]`

| Key | Values | Gates in the protocol |
| --- | --- | --- |
| `documents` | `none` (default), `read`, `write` | `text`, `range`, `diagnostics`, `hover` need read (`write` includes it); `replace`, `insert` need write |
| `project` | `none` (default), `read`, `write` | the project folder on disk, enforced by the kernel sandbox on Linux and macOS (Windows relies on the declaration) |
| `home` | `none` (default), `read` | the user's home outside the project (the same) |
| `network` | `no` (default), `yes` | (the same) |
| `terminal` | `no` (default), `yes` | `term` |
| `run` | program names, space separated | programs the extension may start (the same); the state folder `$RHUN_STATE` is always writable |

A request without its capability is answered `error ID needs documents=write` and nothing
happens. The install dialog and Settings show the block in words.

## 6. Documents and positions

- A **document id** `DOC` is an integer, unique for the session, given in `opened`. A closed
  and reopened file gets a new id; a reloaded file keeps its id and gets a new version.
- A **version** is an integer that increases with every change the user or an extension makes;
  by how much is not specified (a `replace` that deletes and inserts counts twice). Equal
  versions mean identical text. `opened`, `saved`, `changed`, `text` and `range` carry it;
  `replace` and `insert` require the current one.
- A **position** is `LINE COL`: 1-based line, 1-based **byte** column within the line's UTF-8
  bytes. `COL` must not fall inside a multibyte sequence (`badpos`). `COL` may be one past the
  line's last byte, which is the position of the line's LF (or the end of the document on the
  last line). A **range** `L1 C1 L2 C2` is half-open: from the first position up to, not
  including, the second; a range that ends at `L+1 1` includes line L's LF. Documents with CRLF
  endings report positions on the stored bytes.
- The **text** of a document is its bytes as rhun stores them: lines end in LF. A file with CRLF
  endings is converted when read and written back with CRLF; the protocol never sees CR.
- An extension that subscribes to `edits` receives every change as deltas (the `edits` event)
  and keeps its own copy of the text in step; `resync` tells it that deltas were lost and it
  must fetch `text` again. An extension that subscribes only to `changed` fetches what it
  needs when it needs it. Choose `changed` + `text` for a whole-document pass (a checker, a
  formatter), `edits` when a copy of the text must stay in step cheaply (a language server).
  Both report the extension's own `replace` and `insert` too.

### 6a. The `edits` body

One record per change, in the order they happened, each applying to the text as the previous
record left it:

```
START DEL INS
<INS bytes>
```

`START` is a byte offset from the start of the document, `DEL` the number of bytes deleted
there, `INS` the number of bytes inserted there (the bytes follow the record's LF; the next
record starts right after them). A keystroke is one record; a paste one; an extension's
`replace` is a delete record and an insert record. Undo and redo are records too. The event's
`VERSION` is the document's version after the last record; an extension that applies them to
its copy of the text at the previous version has the text at `VERSION`. Positions in records
are byte offsets because that is what the editor has; converting them to lines is the
extension's job, and it has the text to do it with.

### 6b. Diagnostics

Each line of a `diagnostics` body is `L1 C1 L2 C2 SEVERITY MESSAGE`: a half-open range of the
document at the given version, a severity among `error`, `warning`, `info` and `hint`, and the
message to show (the rest of the line; no line feeds). rhun draws a dot in the gutter and an
underline under the range, counts errors and warnings in the status bar, and shows the message
when the pointer rests on the range. Marks move with later edits (a mark whose range is deleted
disappears); an extension that wants exact marks sends them again after `changed`. Marks belong
to the extension that sent them: another extension's marks on the same document are untouched,
and they are removed when the extension stops. A range ending at `L+1 1` marks the line's end.

### 6c. Per-document options

`option DOC KEY VALUE` overrides one of the user's settings for one document: `tab_width`
(1 to 16), `insert_spaces`, `trim_trailing_whitespace`, `final_newline` (`yes` or `no`);
`VALUE` `-` removes this extension's override of that key. Precedence is extension over user
over default; when two extensions set the same key the last writer wins; an override is removed
when its extension stops or the document closes, and the user's setting applies again. Options
never reach the config file. An unknown key or value is `syntax`.

## 7. Limits

| What | Limit | On overflow |
| --- | --- | --- |
| a line | 65536 bytes | the extension is stopped ("a line over 64 KB without an end") |
| `replace`, `insert` body | 4 MB | the extension is stopped ("a body over its cap"): rhun will not read megabytes to discard them |
| `diagnostics` | 2000 lines; a message 200 bytes | `toobig`; messages are cut |
| `hover` body | 4000 bytes | cut |
| pending `edits` per document per frame | 1 MB | the records are dropped and `resync` is sent |
| `toast` body | 200 bytes | truncated at a character boundary |
| `choose` | 1000 items; the prompt and each item 200 bytes | `toobig`; cut at a character boundary |
| `ask` prompt | 200 bytes | cut |
| `term` body | 4096 bytes; plain text only | `toobig`; `syntax` |
| `register` | 64 commands per extension; `NAME` 40 bytes, `TITLE` 80 bytes | `toobig`; `syntax`; cut |
| `status` body | 80 bytes | truncated at a character boundary |
| rhun's outgoing queue per extension | 1 MB; stopped after 10 s full; 8 MB stops it at once | stopped: "not reading" |
| one parsing run | 2 ms | the rest waits for the next window |
| messages from one extension per 16 ms window | 500 messages or 256 KB | the rest waits for the next window; 30 windows in a row with 100 messages or 64 KB or more is "flooding" and stops it |

## 8. Messages

### Events from rhun (id 0)

| Event | Fields | When |
| --- | --- | --- |
| `ready` | `PROJECT` | after `hello`; `-` without a project |
| `opened` | `DOC VERSION LANG PATH` | a document the `opened` subscription matches is opened, and at catch-up; `LANG` is the grammar name with spaces as `_` (`Visual_Basic`) or `-`; `PATH` absolute or `-` for an untitled document; PATH is the last field and may contain spaces (a path with a line feed in it is not supported) |
| `active` | `DOC` | the active tab changed, and at catch-up (`0` when no document is active) |
| `saved` | `DOC VERSION` | the document was written to disk |
| `changed` | `DOC VERSION` | the document changed, by the user or by any extension's `replace`/`insert` (this one's included); at most once per frame per document |
| `cursor` | `DOC LINE COL` | the cursor moved, with or without a selection; once per frame; also for the document that just became active, so a subscriber always knows the active document's cursor |
| `selection` | `DOC L1 C1 L2 C2` | a selection exists and changed, or just collapsed (then both positions are equal); once per frame; `L1 C1` is the anchor, `L2 C2` the cursor |
| `closed` | `DOC` | the tab closed |
| `project` | `PATH` | the project changed (`-` when closed); `on = project` extensions start again for the new one |
| `run` | `COMMAND DOC` | one of the extension's commands was invoked, by its full name `NAME.command`; `DOC` is the active document or `0`. It follows the frame's other events (`opened`, `active`, `cursor`, …), and the catch-up when the command started the extension, so what it names is known by then. There is no request for the cursor: an extension that needs it subscribes to `cursor` |
| `bye` | | rhun is about to stop the extension |
| `edits` | `DOC VERSION LEN` + body | the changes since the last frame to a document the `edits` subscription names, as records that lead from the text the extension has to the text at `VERSION` (section 6a); not sent for the frame in which the document was reported `opened` |
| `resync` | `DOC VERSION` | deltas were lost (more than 1 MB of edits piled up in one frame): fetch `text`. A reload from disk arrives as deltas |
| `hover` | `DOC LINE COL` | the pointer has rested half a second on that position of a document the `hover` subscription names; answer with a `hover` request to show something, or not at all |

### Requests from the extension

| Request | Reply | Needs | Effect |
| --- | --- | --- | --- |
| `ID text DOC` | `ok ID VERSION LEN` + body | documents read | the whole text |
| `ID range DOC L1 C1 L2 C2` | `ok ID VERSION LEN` + body | documents read | the bytes of the range |
| `ID replace DOC VERSION L1 C1 L2 C2 LEN` + body | `ok ID NEWVERSION` | documents write | replaces the range with the body as one undo step, if `VERSION` is current (`stale` otherwise); the cursor inside the range moves to the end of the new text; the body is inserted as given (bytes, no conversion) |
| `ID insert DOC VERSION LEN` + body | `ok ID NEWVERSION` | documents write | inserts at the cursor, replacing the selection if any |
| `ID select DOC L1 C1 L2 C2` | `ok ID` | | selects the range with the cursor at `L2 C2`; equal positions place the cursor; a document that is not on screen keeps the positions for when it is |
| `ID toast LEN` + body | `ok ID` | | a message on screen for two seconds |
| `ID status LEN` + body | `ok ID` | | the extension's status-bar text; an empty body clears it |
| `ID open LINE COL PATH` | `ok ID DOC` | | opens an existing text file in a tab (or activates its tab) with the cursor at the position, clamped to the document; `0 0` keeps the file's cursor; a relative PATH is inside the project; `nofile` for a missing file, `nodoc` for an image; the `opened` event follows at the next frame |
| `ID cancel ID2` | `ok ID` | | withdraws request `ID2` if rhun has not started on it |
| `ID register NAME KEYS TITLE` | `ok ID` | | a command for this session: `EXTENSION.NAME` in the palette as "TITLE (Extension)", with the default key `KEYS` (one combination with a modifier, `ctrl+alt+k`; `-` for none; the user's `[keys]` and keys already bound win, and a bare key is ignored); it is invoked like a manifest command (the `run` event) and removed when the extension stops; `NAME` is `[a-z0-9_]+`; a name in use is `refused` |
| `ID option DOC KEY VALUE` | `ok ID` | documents write for `trim_trailing_whitespace` and `final_newline` (they change what is saved) | a per-document setting (section 6c), until the document closes or the extension stops; `VALUE` `-` removes this extension's override |
| `ID choose LEN` + body | `ok ID N` | | a pick list in the palette: the body's first line is the prompt, the other lines the items; the user filters and picks, and `N` is the 1-based number of the item picked; `error ID cancelled` when the user dismisses it; `busy` while a prompt or the palette is open |
| `ID ask LEN` + body | `ok ID LEN` + body | | a text prompt with the body as its label; the answer comes back as the reply's body (empty when the user entered nothing); `cancelled`, `busy` as for `choose` |
| `ID term LEN` + body | `ok ID` | terminal | the body, one line of plain text (valid UTF-8; no control, C1, bidi-control or zero-width characters: `syntax`), shown from its start in rhun's prompt; the user edits it, and Enter (not within the first half second) types it into the terminal panel's shell (opened if needed), after Ctrl-U clears the shell's line, and answers `ok`; Esc or an empty line answers `cancelled`; `busy` as for `choose`. The command never reaches the shell without that step |
| `ID cmd NAME` | `ok ID` | per command (section 8a) | runs one of rhun's own commands, among those of section 8a, as if the user had invoked it; any other name is `refused` |
| `ID diagnostics DOC VERSION N LEN` + body | `ok ID` | documents read | replaces this extension's marks on the document with the `N` lines of the body (section 6b) if `VERSION` is current (`stale` otherwise); `N` is 0 to clear; at most 2000 |
| `ID hover DOC LINE COL LEN` + body | `ok ID` | documents read | the text to show at that position; shown only while the pointer still rests there; at most 4000 bytes. Positions refer to the current text (a reply that arrives after an edit may be off; rhun does not check). When a diagnostic's range covers the position, its message is shown instead |

### 8a. The commands `cmd` may run

Editing, with `documents = write`: `undo`, `redo`, `duplicate_line`, `delete_line`,
`move_line_up`, `move_line_down`, `indent`, `outdent`, `toggle_comment`, `newline_below`,
`newline_above`. Selection: `select_all`, `select_line`, `select_next`. Navigation and search:
`find`, `replace`, `find_next`, `find_prev`, `find_in_files`, `goto_line`, `quick_open`,
`command_palette`, `next_tab`, `prev_tab`, `reveal_file`, `focus_explorer`. View:
`toggle_sidebar`, `toggle_agents`, `toggle_word_wrap`, `toggle_whitespace`,
`toggle_line_numbers`, `zoom_in`, `zoom_out`, `zoom_reset`. Terminal, with `terminal = yes`:
`toggle_terminal`, `new_terminal`, `clear_terminal`. A command whose capability the manifest
lacks is `needs`. Nothing that saves, closes, opens or deletes files, quits, changes settings or
the theme, touches the clipboard (`cut`, `copy`, `paste`: a paste can reach the terminal),
git, the agents or updates, or kills a terminal.

Prompts are one at a time for the whole editor: a second `choose`, `ask` or `term` while one
is open, or while the user has the palette open, is `busy`. The user opening the palette,
the extension stopping, or `cancel` end an open prompt with `cancelled`.

### Requests from rhun

None in v1: everything rhun sends is an event. The request form from rhun (`ID verb …`, answered
by the extension with `ok ID` or `error ID CODE`) is reserved for later versions; an extension
that receives a line starting with a non-zero number should answer `error ID unknown`.

## 9. An exchange

```
→ hello 1
← 0 ready /home/me/app
← 0 opened 1 3 Go /home/me/app/main.go
← 0 active 1
← 0 run format.format_document 1
→ 7 text 1
← ok 7 3 41
← package main

func  main() { println("x") }
→ 8 replace 1 3 1 1 4 1 38
→ package main

func main() { println("x") }
← ok 8 4
← 0 changed 1 4
```

## 10. Testing an extension

`rhun PROJECT --headless 1000x600 --scale 1 --extensions DIR --script test.txt` runs rhun
without a display, with the extensions found under `DIR` (laid out as installed:
`DIR/OWNER/NAME/extension.ini`; such a session passes rhun's own environment on to the
programs, so a test can reach them through variables). The state folder is
`$XDG_STATE_HOME/rhun/extensions/OWNER--NAME` (`~/.local/state` when the variable is unset, on
every system), so a test sets `XDG_STATE_HOME` to a folder of its own and seeds files there. The
script is one command per line; what a command prints goes to standard output. The ones an
extension's test needs:

| Command | Does |
| --- | --- |
| `wait MS` | runs the event loop for that long. The frame that follows a step sends its events; the extension's replies land in a later poll: use two `wait 300` lines after a step before reading its effect |
| `open PATH` | opens a file in a tab |
| `cmd NAME.command` | invokes a command by name (an extension's starts it) |
| `type TEXT` | types text into the focused field or document (trailing spaces are dropped: `key space` for those) |
| `key COMBO` | one key or combination per line, as in `[keys]`: `Return`, `Escape`, `Tab`, `space`, `ctrl+End`, `ctrl+Tab`, `ctrl+alt+9` |
| `move X Y` | moves the pointer to a window pixel (a hover event follows after half a second) |
| `print-text-cell LINE COL` | `X Y`, the pixel of that cell of the active document, for `move` |
| `wait-ext NAME STATE` | waits until an extension is `running`, `stopped` or `crashed`; prints `ext=NAME state=STATE` |
| `print-extensions` | one line per extension: `OWNER/NAME state=S pid=P cmds=a,b [status=TEXT]` (registered commands included) |
| `print-state` | `tabs=N active=NAME line=L col=C sel=BYTES dirty=D lang=LANG …` |
| `print-doc` | the active document's text, then `<eod>` |
| `print-marks` | one line per mark of the active document, `L1 C1 L2 C2 SEVERITY OWNER/NAME MESSAGE`, then `errors=N warnings=N` |
| `print-hover` | `hover=DOC LINE COL sent=S text=T` for the position the pointer rests on (`sent` 1 once the event went out, `text` the extension's answer), or `hover=none` |
| `print-tip` | the tooltip on screen (a mark's message or a hover text), `tip=` when none |
| `print-toast` | `toast=TEXT`, or `toast=` |
| `print-palette` | `choose=PROMPT` or `prompt=LABEL` when an extension's prompt is open, `field=TEXT`, then the rows with `> ` on the selected one; `none` when closed |
| `print-options` | `tab_width=N insert_spaces=B trim_trailing_whitespace=B final_newline=B` for the active document |
| `wait-term TEXT`, `print-term` | waits until the terminal's screen shows the text (10 s at most); prints the screen |
| `quit` | ends the session |

`rhun-ext-check DIR` (built from `conformance/ext` in `rhun-editor/extension-protocol`) plays
rhun's side against an installed-layout extension folder without rhun: grammar, ids, positions,
versions, bodies, limits, and that the program survives an unknown event, an error reply,
fragmented input, a burst of events, `bye` and the end of its input. The template's
`tests/run.sh` shows a headless test from start to end.
