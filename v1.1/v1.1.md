# rhun extension protocol 1.1

Protocol 1.1 extends [version 1](v1.md). Existing messages keep their v1 meaning and framing.
The first line remains `hello 1 FEATURES...`; `RHUN_PROTOCOL=1.1` advertises the host's maximum
protocol revision. An extension sends new requests only after rhun agrees to their feature in
the `0 features` event before `ready`. A host that does not know a feature ignores its name.
Feature agreement examines the complete bounded hello line, including names after unknown
features. Decimal fields must fit their documented bounds without wrapping. A malformed body
length ends the extension stream; a bounded body on a stray provider reply is drained before
the next message is parsed.

## Command identity

The host accepts `OWNER/NAME.command` in user key bindings and command lookup. The command
palette shows this identity beside its title and shortcut, and searches it as well as the title.
An exact qualified query selects that command alone, before fuzzy matching.

The shorter `NAME.command` alias remains available when exactly one installed, non-removed
extension has that extension name. An ambiguous alias does not invoke either command, even
when only one owner currently registers that local command. A disabled extension still counts
toward ambiguity, so disabling one does not reroute a saved shortcut to another publisher.
The same rule applies to a short extension name in host controls: use
`OWNER/NAME` when more than one publisher uses the name.

Names in `0 run NAME.command DOC` events stay unchanged. Runtime `register` names are local
to the extension. Another publisher's equal extension or command name does not prevent
registration; an extension cannot register over its own manifest or runtime command.

## Feature: `commands`

An extension lists `commands` in `hello 1 ...`. When the host agrees, it may send:

| Request | Reply | Effect |
| --- | --- | --- |
| `ID unregister NAME` | `ok ID` | removes the caller's runtime command, its default shortcut, and its palette entry |

`NAME` has the same grammar as `register`: 1 to 40 lowercase ASCII letters, digits or underscores.
It names the local command, without the extension prefix. Missing commands and manifest
commands return `error ID refused not a runtime command of this extension`. Malformed names
return `syntax`. Without agreed `commands`, the request returns `unknown` and changes nothing.

Removing one command preserves the caller's other commands and all other extensions' commands.
The same name can be registered again after removal. Existing user key-binding configuration is
kept, so its binding returns if that runtime command is registered again. An open command palette
closes when its command storage changes; other menus resolve their saved command names again
when clicked.

## Feature: `workspace_watch`

Extensions can subscribe to coalesced filesystem invalidations for the current workspace.
Declare `project = read` (or `write`) in `[needs]`, request `workspace_watch` in `hello 1`,
and wait for feature agreement before subscribing. This feature grants no additional file access.

| Request | Reply | Effect |
| --- | --- | --- |
| `ID watch-workspace` | `ok ID HANDLE` | subscribes the current runtime to workspace invalidations |
| `ID unwatch-workspace HANDLE` | `ok ID` | removes that runtime's subscription |

The host sends `0 watch HANDLE changed` when it observes a possible change, and
`0 watch HANDLE rescan` when the extension should recover its view of the workspace.
Both events require reconciliation with disk. Events can combine multiple changes or repeat;
they do not enumerate operations, preserve every intermediate state, or identify changed paths.
Hidden directories are included. Extensions must not infer deletions from an incomplete scan.

Handles are positive integers through 2147483647, owned by one runtime. Repeated subscription
returns its existing handle. Another runtime cannot remove it. Stop, process exit and workspace
change retire subscriptions; subscribe again for the new runtime or workspace. Stale handles
are never reassigned. Missing permission or workspace, exhausted capacity and invalid requests
return an error without creating a subscription.

The host shares directory watches across subscribers and preserves its editor watches when a
subscription ends. It bounds subscriptions to 128 and tree coverage to 512 directories, 32768
entries and 4095-byte paths, with at most 4096 entries per directory. Incomplete coverage uses
recovery invalidations, including a two-second periodic rescan signal. A subscriber must bound
its own scanning and preserve its previous view when reconciliation fails.

Go exposes `WatchWorkspaceContext`, `UnwatchWorkspaceContext` and `ParseWorkspaceWatch`;
Rust exposes `watch_workspace`, `unwatch_workspace` and `parse_workspace_watch`;
C exposes `rx_watch_workspace`, `rx_unwatch_workspace` and `rx_parse_workspace_watch`.

## Single-provider selection

Formatting, rename, document symbols and signature help use a per-language provider preference. These are host
settings, so extensions keep their existing v1 provider declarations and request/reply messages.
When several providers match and no default exists, the host asks the user and saves the
qualified `owner/name` choice. Definitions, references and code actions keep their combined
results from matching providers.

A request waits up to five seconds for the selected extension to become ready, including time
waiting for a process slot. The host rechecks the document, selection, path, language, manifest
patterns and negotiated feature before sending it. An unavailable preference is an actionable
error, with no fallback. Explicit actions may start an idle or crashed extension; a user-stopped
or disabled extension stays stopped until the user enables or restarts it.

Headless controls for testing are `provider-set KIND LANGUAGE OWNER/NAME`,
`provider-set KIND LANGUAGE -` to clear, and `print-providers`. Kinds are `format`, `rename` and
`symbols`, and `signature`. The control command takes single-word languages; the INI file also accepts language
names containing spaces.

Automatic signature triggers do not show a chooser or an unavailable-provider error. Without a
saved preference they use a sole eligible provider only when it is running; competing idle or
starting providers make the choice ambiguous too. A shown or pending signature session keeps
its original provider for both triggers and updates, even if the saved preference changes.
Explicit Show Signature Help closes that session and resolves the current choice afresh.

## Managed saves

The optional host setting `[files] format_on_save = true` uses the existing native format
request and workspace-edit reply before writing. It adds no wire feature. The default is false;
`format_on_save_timeout` defaults to 2,000 milliseconds and accepts 250 through 30,000.

Automatic saves use the saved formatter or a sole eligible provider, including cold activation
within the deadline. They never show a chooser or restart a user-stopped provider. If formatting
is unavailable, ambiguous, fails or times out, the current buffer is saved with a warning.
The document's ID, destination and version are rechecked before applying a reply. A stale reply
is discarded and the latest buffer is saved. A formatter's edit can only target the existing
document being saved; a foreign group rejects the entire edit without opening tabs.

Save cancellation sends `0 cancel ID` for an outstanding format request and performs no write.
Closing or retargeting the document cancels its old save, and late replies are ignored. Save
Without Formatting cancels the request and writes the current text. Save-before-close and
Save All continue only after the actual file write succeeds.

## Capacity and shared scheduling

The host can run all 128 installed extension records concurrently. The earlier 16-process
limit no longer holds matching providers idle behind extensions that stay running. The editor
reserves enough event watches for their input and output pipes plus its other services. On
Linux and macOS it raises its descriptor soft limit toward 1,024 when the inherited hard limit
permits, preserving larger inherited limits. A restricted hard limit can still constrain starts.

Parsing has a shared soft budget per 16 ms window: 4 ms of work, 2,000 message steps or 1 MiB
consumed, whichever comes first. A framed header and its completed body each count as a message
step. Existing per-extension message, byte, time and flood limits still apply. A complete message
handler is atomic and may exceed the soft time/byte budget; subsequent work waits. Shared
throttling alone does not count as flooding. Suspended programs resume in rotating order, with
both their own and the shared deadlines respected.

Stop also cancels queued restarts, an idle activation and queued commands, so it cannot start later without an
explicit restart. `print-ext-budget` reports cumulative windows/yields and the highest message
and byte totals seen in a shared window for headless checks.

## Text snapshots and document events

Before answering `text DOC`, the host sends pending document events through the returned
version. An extension that replaces its cache with the reply can discard queued edit or resync
events at that version or earlier. Later edit batches begin after the snapshot, so they can be
applied without repeating changes already included in the text. Repeated text reads do not
repeat a resync event for the same version.

## Feature: `save-actions`

A provider declares `[provides] save_actions = PATTERNS`, `documents = write` in `[needs]`,
and `save-actions` in `hello 1 ...`. A matching document activates it and receives the same
opened and edits stream as other language providers. The host agrees to the feature before
ready. Protocol 1.1's complete manifest schema is [v1.1.json](https://github.com/rhun-editor/extension-protocol/blob/main/v1.1/v1.1.json); the frozen v1 schema
remains unchanged.

The opt-in `[files] code_actions_on_save` setting lists source kinds separated by spaces.
Each kind is `source` or a hierarchy such as `source.organizeImports` or `source.fixAll.eslint`.
Segments contain ASCII letters, digits, underscores or hyphens. A kind is at most 128 bytes,
with at most 32 kinds and 4,096 bytes in the setting. Empty disables it. An ancestor covers its
listed descendants, so `source source.fixAll` runs `source` once. Invalid changes preserve the
previous valid setting and show a warning. `code_actions_on_save_timeout` defaults to 2,000
milliseconds and accepts 250 through 30,000. This is one deadline for the whole source phase,
including activation. Source actions precede formatting, which has its own deadline.

Eligible matching providers run in qualified `owner/name` order for each configured kind.
Disabled, user-stopped, failed and unnegotiated providers are skipped. No matching provider is
quiet. Errors or a timeout skip the remaining source phase and continue to formatting with a
warning. A user edit makes the remaining automatic transforms stale; the current text is saved.
Save Without Formatting bypasses all automatic save participants.

| Direction | Request | Successful reply |
| --- | --- | --- |
| Host to extension | `ID save-actions DOC VERSION KIND` | `ok ID LEN` followed by a workspace edit, or `ok ID 0` |
| Extension to host | `ID save-apply SAVE_REQUEST DOC VERSION LEN` followed by a workspace edit | `ok ID NEW_VERSION` |

`SAVE_REQUEST` is the host's active source request ID. Request IDs are 1 through 2147483647,
DOC is positive, and VERSION is nonnegative. The ordinary workspace-edit limits apply.
A returned or intermediate edit may only target the existing saving document. Any foreign
group rejects the whole edit before opening files. Empty edits do not advance its version.
Intermediate edits require agreed `save-actions`, documents write authority, the same peer,
request and document, and the live version last credited by that save. A wrong or retired
invocation returns `refused`; an obsolete version returns `stale`. Ordinary `apply` does not
advance the save's credited version. After intermediate edits, the final reply uses their
credited version for its workspace edit, or an empty edit when there is nothing left to apply.

The host revokes intermediate authority before sending `0 cancel SAVE_REQUEST`, saving,
retargeting or closing the document. Late intermediate edits are rejected and late final replies
are ignored. Extensions must observe cancellation and bound their work. Go's typed handler
receives a context cancelled directly by the input reader; Rust and C handlers are serial, so
custom asynchronous dispatchers must use the cancel event's request ID to retire their work.

## Feature: `snippets`

This feature adds native editable fields to prepared UTF-8 text. It uses the existing
`complete` provider; no new manifest property is needed. A completion's INSERT contains expanded
text, and EXTRA may contain records with no following body:

```
field GROUP START END PARENT 0
```

START and END are half-open byte offsets into INSERT, on UTF-8 character boundaries. GROUP is
0 through 2147483647. The first occurrence of a positive group is its primary editable field;
other occurrences are linked mirrors and must initially contain identical bytes. Group 0 is
an optional single final selection, empty for a caret. Without it, the final caret is INSERT's end. Positive
groups are visited in increasing numerical order, with 0 last. Empty prepared text stays empty,
even when the completion has a nonempty label. Existing cursor metadata remains a fallback for
hosts that do not agree to snippets. Invalid field metadata is ignored as a whole by completion
acceptance, leaving plain INSERT and its ordinary cursor behavior.

PARENT is 0 for a root, or the one-based index of an earlier field record that is a different
positive group's primary. That primary must contain this occurrence. Mirrors cannot contain
child fields. Overlapping nonempty ranges, and empty ranges strictly inside nonempty ranges,
must follow their declared ancestor chain. Coextensive parent and child ranges are allowed;
unrelated empty fields may coincide at boundaries. Same-group occurrences cannot overlap or
nest. Each occurrence's group depends on its containing primary ancestor groups; cycles in
this group dependency graph are invalid even when the record-parent graph is acyclic.

The final marker is non-owning: it may overlap or cross other fields, creates no group
propagation dependency, and cannot be another record's parent. Its own PARENT, when nonzero,
must contain the whole final selection. Advancing past the positive groups selects this range
and finishes the innermost session. An initially nonempty final range follows edits to its
content without absorbing adjacent fields. If deletion collapses the range, later typing in
the same occurrence restores the range; typing in a different occurrence keeps its boundary.
Initially empty final markers retain their rightward caret affinity.

A primary group can offer literal values using a separate EXTRA record, before or after fields:

```
choice GROUP COUNT LEN
```

The LEN-byte body contains exactly COUNT options. Each option is `OPTION_LEN` and LF followed
by exactly OPTION_LEN UTF-8 bytes. Options can be empty, multiline, or contain NUL. GROUP must
name a positive primary group, with only one choice record per group. COUNT is 1 through 256,
and each option is at most 1 MiB. The first option must equal the initial primary bytes. Choice
records and fields are validated together. One bad choice invalidates all new snippet metadata.
Choices remain native after the provider stops. Freeform field editing remains available.
The host displays all choices in declared order. Enter or a click replaces the entire active
primary and keeps the field active; Tab also advances once. Shift+Tab closes without applying
and moves to the previous field. Escape closes choices before ending field editing. Choosing
the same bytes does not create an undo record. The Choose Value command reopens the list.
Explicit provider completion from an exactly selected active primary collapses to its end;
ordinary provider request position and replacement-range rules then apply.

Limits are 512 field records, 256 positive groups, nesting depth 32, and 4 MiB for an explicit
prepared record including framing. Existing completion-list limits still apply. A completion
on an older host keeps its plain text; that host skips unknown EXTRA records using their declared body lengths.
Extensions must check agreement before using the explicit insertion request:

```
ID snippet DOC VERSION L1 C1 L2 C2 LEN
```

The LEN-byte body is one prepared completion-item record, without a list header:

```
0 0 0 0 snippet 0 INSERT_LEN 0 EXTRA_LEN
```

Exactly INSERT_LEN text bytes and EXTRA_LEN field and choice record bytes follow the header. No label,
detail, documentation, extra edit, or unknown record is allowed in this explicit body. DOC is
a positive existing document ID, VERSION is nonnegative and exact, and the range uses positive
one-based lines and byte columns. Documents write authority and a writable document are required.
The host validates the entire request before replacing the range. Invalid explicit metadata
rejects the request without edits. Success replies `ok ID NEW_VERSION`, selects the first
positive field, and starts a session without switching to an inactive target tab. Fieldless
text inserts normally; final-only metadata selects its range and finishes immediately.

Tab and Shift+Tab move through fields, and Escape ends the session. A completion popup takes
its keys first. Accepted sessions are independent of the provider process. Inactive tabs retain
their session. Undo and redo, reloading, readonly state, non-user document mutations, or moving
the selection outside the active primary end the session. Returning the selection cannot revive
it. Each user edit and its mirror updates undo together.
Replacing or editing through a parent field retires affected nested fields. Retiring a primary
retires its whole group; external mirror text remains as ordinary text. Retiring only a mirror
leaves its primary and other mirrors live. The final marker survives field retirement.

Inserting a prepared snippet within the active primary pauses the enclosing session. Inner
field numbers are local. Tab after the inner final field returns to its final caret and resumes
the enclosing field; the next Tab continues the enclosing field order. Shift+Tab at the first
inner field stays there. Escape ends every enclosing level. Fieldless and final-only insertions
retain enclosing links without adding a navigation level. Ordinary completions also retain
those links when all their edits fit inside the active primary. Invalid completion field data
is discarded without discarding valid enclosing links. An additional edit outside that primary
ends the old session before accepting the completion. The same applies when a new positive-field
session would exceed 32 levels, 512 total occurrences, 256 total groups, or 4 MiB of retained choice payload across the stack.
The new snippet still inserts and starts independently. Malformed explicit insertion leaves
the existing stack unchanged.

Mirrors propagate in group dependency order. A nonempty replacement preserves its original
left and right boundary positions, so a surviving empty field at the old end stays after the
new text. For originally coincident empty occurrences, record order determines side affinity.
The host preflights the complete propagation, including ancestors, before mirror writes. If
the operation would insert more than 4 MiB through mirroring across all enclosing levels, it ends the session and retains
the primary user input without making a partial mirror batch. Template parsing, variables
and transforms are separate from this prepared-text wire representation.

### Read-only insertion context

After agreeing to `snippets`, an extension with documents read authority can request:

```
ID snippet-context DOC VERSION L1 C1 L2 C2
```

There is no request body. DOC must name an open document, VERSION must match exactly, and
the ordered range uses positive one-based line and byte columns at UTF-8 boundaries. All
numbers are unsigned decimal within signed 64-bit range; ID is 1 through 2147483647. The
request has exactly these eight fields. Readonly documents and inactive tabs are allowed.
It does not move the cursor, change the selection, edit the document, or grant write authority.

Success is `ok ID VERSION LEN` followed by exactly LEN bytes. The body begins:

```
context 1 LINE COL TABWIDTH SPACES CRLF SELECTED_LEN LINE_LEN PATH_LEN WORKSPACE_LEN INDENT_LEN COMMENT_LEN
```

LF ends the header. Exactly six raw UTF-8 strings follow in the listed order, without separators:

| String | Meaning |
| --- | --- |
| Selected text | The exact requested range, independent of the editor's current selection |
| Current line | The range start's line, excluding its newline |
| Path | The document's absolute display path, or empty for an untitled document |
| Workspace | The current project root, or empty without a project |
| Indentation | Leading spaces and tabs up to the range start, stopping at the first other byte |
| Line comment | The grammar's line-comment token, or empty when unavailable |

LINE and COL repeat L1 and C1. TABWIDTH is the target document's effective width, 1 through 16.
SPACES and CRLF are 0 or 1. These settings include the target document's option overrides.
The six strings may contain NUL; selected text may contain line breaks. Body framing uses
byte lengths throughout. The header is at most 256 bytes excluding LF. The complete body,
including header and strings, is at most 4 MiB. The host rejects larger snapshots with `toobig`
and invalid UTF-8 with `refused`, without truncation. Standard `syntax`, `needs`, `unknown`,
`nodoc`, `badpos`, and `stale CURRENTVERSION` errors also apply.

Pending document events precede a successful context reply. This partial snapshot does not
replace a whole-document text cache. An extension can prepare a snippet using these values
and insert it using the same version and range; an intervening edit produces `stale`.
The context contains no clipboard contents, environment values, clock or random data.


### Declared initial mirror variants

The additive `snippet-variants` feature requires `snippets` as well. With both agreed, a
prepared program's EXTRA may include `variant FIELD 0` followed by LF, with no body.
FIELD is the one-based field-record index, 1 through 512. Declarations may precede or
follow fields and choices. At most 512 distinct declarations are allowed. Each must name
an existing positive-group mirror whose initial bytes differ from its primary. Primary
fields, final selections, equal copies, duplicate declarations and absent indices are invalid.
Decimal indices accept leading zeroes; the final body-length token must be exactly `0`.
All ordinary field, UTF-8, ancestry, graph, choice and encoded-size constraints still apply.
An unequal mirror without a declaration is invalid. Choice option zero still matches the primary.

A variant changes only initial validation. After an edit to its group, the native editor copies
the primary value to ordinary mirrors using the existing undo and navigation behavior.
Declarations do not execute transforms or retain a dependency on the extension process.

Explicit insertion requires agreement and rejects invalid metadata atomically. For completion,
invalid or unnegotiated metadata is discarded together while the insertion text remains usable.
Older hosts skip the unknown zero-body record and reject the unequal field bytes, producing
the same plain-text fallback. Extension authors must check both features before emitting variants.
Plain prepared-snippet SDK validation remains strict; use the program API for declarations.

### Compiled field transforms

The additive `snippet-transforms` feature requires `snippets`. When both are agreed,
EXTRA may contain one `transforms 0 LEN` header followed by LF and exactly LEN ASCII
bytes. The reserved token is exactly `0`. The body is canonical RFC 4648 standard
Base64 with required padding. Whitespace, line breaks, the URL alphabet, misplaced
padding and nonzero unused bits are invalid. The record may precede or follow fields,
choices and variants. A second record is invalid, including an empty binding payload.

The decoded body is an SNTX program. Each binding names an existing one-based field
index, 1 through 512, in a positive group. Primaries and mirrors may both have transforms;
final selections cannot. Initial bytes still obey ordinary equality or explicit variant
rules. The SDK encoders sort bindings by field index without changing caller arrays.
The host owns validated programs independently of the extension process.

On Tab or Shift+Tab, every alive transformed occurrence in the group being left uses
its own current value. Typing still copies the primary value to ordinary mirrors.
Initial activation and cancellation do not run transforms. Shift+Tab at the first group
runs the group and reselects it; revisiting a group runs its transforms again. Outputs
are prepared together, including enclosing mirror propagation, then applied as one undo
group before selecting the destination. Failure preserves document text and selection
and ends the live session. The batch has a shared 16,777,216 work-unit budget, 50 ms
deadline and 4 MiB inserted-byte cap. Output comparison, case conversion, matching and
indentation share the budget. Undo and redo restore the complete accepted change.

The first output line keeps its whitespace. CRLF, CR and LF become LF. Each later line,
including a trailing empty line, receives the original insertion line's leading ASCII
spaces and tabs, then normalization with the document's current tab width and spaces
setting. Completion captures this prefix at its main edit before additional edits.
The captured prefix, choices and compiled programs share the existing 4 MiB aggregate
metadata budget across nested sessions.

All existing encoded-body limits include the Base64 expansion: `4 * ceil(raw_bytes / 3)`
plus the record header. Explicit insertion remains at most 4 MiB and completion lists at
most 1 MiB. SDK encoders reject an invalid explicit-sized program before emitting it.
Invalid completion metadata falls back to insertion text as a whole. A valid program
whose completion item exceeds the completion budget is omitted and marks the list
incomplete. Malformed outer completion or EXTRA framing follows ordinary list rejection.
Unnegotiated transforms reject explicit insertion and discard completion snippet metadata.
Extension authors must check both features before sending this record.

#### Portable binary programs

All integers below are unsigned little-endian 32-bit words. There is no alignment,
terminator, implicit padding, or trailing data. Program version is 1 and Unicode version
is `0x00100000` (Unicode 16.0.0). All reserved words and unused operands must be zero.
Lengths and offsets are in bytes. Validators reject an invalid program before executing it.
Use SDK compilers or import validated compiled programs rather than constructing bytes
from untrusted integers.

SNTX begins with eight words: magic `0x58544e53` (`SNTX`), version, Unicode version,
binding count, total length, and three reserved words. The count is 0 through 512 and
total length is at most 4 MiB. Each 24-byte record contains field index, absolute regex
offset, regex length, absolute replacement offset, replacement length, reserved zero.
Field indices strictly increase. Blobs start immediately after the record table and
partition the rest of the payload: regex then replacement for each binding, without gaps.
A zero-count payload is exactly the 32-byte header. SDKs omit the record for no bindings.

RNRX begins with twelve words: magic `0x58524e52` (`RNRX`), version, Unicode version,
flags, capture count, instruction count, class count, range count, repeat count, entry
instruction index, total length, reserved zero. Flags are `g=1`, `i=2`, `m=4`, `s=8`,
`u=16`, `y=32`, `d=64`; other bits are invalid. Consumption uses Unicode scalars in
both modes, while case equivalence distinguishes `i` and `iu`. Captures are at most 64,
instructions 1 through 8192, classes at most 256, ranges at most 8192 and repeats at most
256. The whole regex is at most 256 KiB. Entry and all branch targets are zero-based
instruction indices. Arrays follow the header in the order below.

Each instruction is four words: opcode, X, Y, Z. A consuming instruction falls through
to the next instruction, which must exist. Unused operands are zero.

| Opcode | Meaning and operands |
| --- | --- |
| 0 | Match/return, no operands. |
| 1 | Match scalar X. |
| 2 | Match dot, no operands. |
| 3 | Match class X. |
| 4 | Assert X: 1 start, 2 end, 3 word boundary, 4 non-boundary. |
| 5 | Save capture slot X; slots 2 through `2*(captures+1)-1`. |
| 6 | Clear Y capture slots starting at X; X and Y even, X at least 2, Y positive. |
| 7 | Split to X then Y, without fallthrough. |
| 8 | Jump to X. |
| 9 | Match capture X, 1 through capture count. |
| 10 | Initialize repeat X, then fall through. |
| 11 | Test repeat X, using body target Y and exit target Z. |
| 12 | Advance repeat X and jump to Y. |
| 13 | Call assertion at X, continue at Y. Z bit 0 negates, bit 1 searches backward. |
| 14 | Assert kind X (1 through 4), with explicit local `i`/`m` bits in Y (mask `0x06`), and Z zero. |
| 15 | Match capture X (1 through capture count), with explicit local `i` bit in Y (`0` or `2`), and Z zero. |

Instructions 14 and 15 fall through to a following instruction, which must exist.
Their Y operand replaces only the indicated flag bits for that operation; other global
flags retain their values. Local flags never persist into later instructions or branches.

Class records are `(first_range, range_count)` pairs that partition the range array in
class order, including empty classes. Ranges are inclusive `(low_scalar, high_scalar)`
pairs, sorted and disjoint within each class, with adjacent ranges merged. Scalars exclude
surrogates; no range may cross the surrogate gap. Repeat records have four words:
minimum, maximum, flags, reserved zero. Counts are at most `0x7fffffff`; maximum may
instead be `0xffffffff` for unbounded. Maximum is otherwise at least minimum. Repeat
flag bit 0 selects lazy order; other bits are invalid. Matching uses bounded backtracking,
rollback and assertion storage. Storage exhaustion fails the whole batch.

RNRF begins with eight words: magic `0x46524e52` (`RNRF`), version, Unicode version,
record count, UTF-8 blob length, total length, and two reserved words. At most 8192
24-byte records follow, then exactly the blob. Total length is at most 4 MiB. Records
contain opcode, capture index, A offset, A length, B offset, B length. Offsets are relative
to the blob. Used strings, including empty ones, partition the blob in record order,
A then B. Unused offset/length pairs are zero. Capture indices are at most `0x7fffffff`;
absent captures resolve as empty. Literal records require index zero.

| Opcode | Result | Strings used |
| --- | --- | --- |
| 0 | Literal A | A |
| 1 | Capture | none |
| 2, 3, 4 | Uppercase, lowercase, capitalize capture | none |
| 5, 6, 7, 8 | Camel, Pascal, snake, kebab case capture | none |
| 9 | A when capture is nonempty | A |
| 10 | Capture when nonempty, otherwise A | A |
| 11 | A when capture is nonempty, otherwise B | A, B |

Transforms preserve unmatched input around replacements. Global zero-width matches
advance the next search by one scalar without dropping intervening text. Sticky matching
starts at the current search offset. If there is no match and the format has a nonempty
else branch, the whole format resolves once with absent captures and replaces the input.
Otherwise a no-match transform preserves the input. Case conversion uses pinned Unicode
full mappings and contextual final sigma. Word case formats use Unicode letters and
ASCII digits.

## Feature: `notebooks`

An extension reads and writes a notebook format, and may run its cells. rhun never parses a
notebook file: the extension turns the file into cells and back. The first-party `jupyter`
extension does this for `.ipynb`.

```ini
[provides]
# notebooks this extension reads and writes (section 2's patterns)
notebook = *.ipynb
notebook.title = Jupyter Notebook
# it runs cells; "no" for a viewer or converter only
notebook.kernel = yes
```

Opening a file a `notebook` pattern matches shows it in a notebook tab and starts the extension
(a user-stopped or disabled one stays stopped, and the tab says so). The tab is a list of cells,
each a text document of its own with its language's colors; outputs show under code cells. The
user can always look at the file as text instead (the failed tab's Open as Text, or the command
Notebook: Reopen as Text on a notebook without changes).

Identifiers rhun hands out, never reused in a session: `NB` a notebook, `CELL` a cell (stable
while the cell exists), `RUN` a run.

### Bodies

A **notebook body**, in both directions:

```
N META_LEN LF <META>
then N cells:   KIND LANG COUNT SOURCE_LEN META_LEN NOUT LF <SOURCE><META>
                then that cell's NOUT output bodies
```

`KIND` is `code` or `markup`. `LANG` is the cell's language, a grammar name with spaces as `_`
(case does not matter: `python` names the Python grammar), or `-`; markup cells are Markdown and
send `-`. `COUNT` is the execution count, or `-`. SOURCE is the cell's text, LF line ends. The
notebook's META and each cell's META (nbformat's cell id, tags, attachments) are opaque: rhun keeps
them and returns them unchanged. A cell rhun creates has empty META and the language of the
notebook's first code cell that names one.

An **output body**:

```
KIND OUTID KEEP_LEN NITEM LF <KEEP>
then NITEM items:  TYPE W H LEN LF <LEN bytes>
```

`KIND` is `stdout`, `stderr`, `result`, `display` or `error`. `OUTID` is `[a-z0-9_.+/-]{1,64}`
(Jupyter's display id) or `-`. KEEP is opaque and returned on save: the jupyter extension keeps
the output's original JSON there, so every MIME bundle round-trips, including the ones rhun cannot
draw. Items are in order of preference and rhun shows the first one it can draw. `TYPE` is `text`
(UTF-8), `ansi` (UTF-8 with SGR colors: 0/1/2/3/4/7/22-24/27/30-37/39/40-47/49/90-97/100-107 and
38/48 with `;5;N` and `;2;R;G;B` apply, every other escape is left out), `png`, `jpeg`, `gif`,
`rich` or `picture` (shown in a later revision), or any other token `[a-z0-9_.+/-]{1,64}`, which
rhun keeps and returns by name. `W H` are the intrinsic logical size of an image (`0 0`: one image
pixel is one logical pixel); a `W` alone keeps the image's proportions. Images are scaled down to
the column, never wider. A text item shows its first 400 rows, then "N more lines · Open in Tab",
which opens all of it, escapes left out, in a read-only tab.

### Messages

| Direction | Message | Reply or meaning |
| --- | --- | --- |
| rhun → ext | `ID nb-open NB LEN` + `PATH_LEN DATA_LEN LF <PATH><DATA>` | `ok ID LEN` + notebook body. DATA is the file's bytes (empty when it does not exist yet: a new notebook). `error ID CODE TEXT` shows TEXT in the tab with Open as Text |
| rhun → ext | `ID nb-save NB LEN` + `PATH_LEN LF <PATH>` + notebook body | `ok ID LEN` + the file's bytes, which rhun writes in place of the file (a temporary file renamed over it). An error keeps the notebook modified and shows its text |
| rhun → ext | `0 nb-run NB CELL RUN LANG LEN` + source | run the cell's source; a run is an event, not a request rhun waits on, and runs of one notebook queue in the extension in the order they arrive |
| rhun → ext | `0 nb-interrupt NB` | the user asked to interrupt the running cell |
| rhun → ext | `0 nb-restart NB` | restart the kernel (the user confirmed) |
| rhun → ext | `0 nb-kernel NB` | the kernel button was clicked: offer kernels, for example with `choose` |
| rhun → ext | `0 nb-closed NB` | the tab closed |
| ext → rhun | `ID nb-state NB CELL RUN STATE COUNT` | `ok ID`. STATE `queued`, `running`, `done`, `failed` or `cancelled`; COUNT a number or `-` (left as it was) |
| ext → rhun | `ID nb-output NB CELL RUN OP TARGET LEN` + output body | `ok ID`. OP `append` (TARGET `-`), `replace` (TARGET the index of one of the cell's outputs, or an OUTID anywhere in the notebook), `clear` (TARGET `-`, LEN 0), `clear-wait` (the outputs clear when the next one arrives; LEN 0) |
| ext → rhun | `ID nb-stream NB CELL RUN NAME LEN` + bytes | `ok ID`. Appends to the cell's last output when it is the `NAME` (`stdout` or `stderr`) stream, else starts one (type `ansi`). CR LF is a line feed; a carriage return alone takes the text back to its line's start, as a progress bar expects |
| ext → rhun | `ID nb-kernel-label NB STATE LEN` + label | `ok ID`. The kernel button's text (one line, at most 200 bytes, cut); STATE `idle`, `busy`, `starting`, `dead` or `none` colors its dot |

Running a cell gives it a new RUN and clears its outputs. Every `nb-state`, `nb-output` and
`nb-stream` names the RUN it belongs to: one for a run that is not the cell's latest, a deleted
cell or a closed notebook is answered `error ID stale`, and nothing changes. Outputs and counts
change the notebook, which then counts as modified, as in Jupyter. When the extension stops, its
queued and running cells show as cancelled and the kernel button clears.

Limits: `nb-open`'s answer and `nb-save`'s body at most 64 MB each (that answer has a cap of its
own; every other answer keeps 4 MB); 5,000 cells; a cell's source 4 MB; 1,000 outputs a cell; 32
items an output; an item 16 MB; an `nb-output` body 17 MB and an `nb-stream` body 64 KB (more
stops the extension, as for any body over its cap); outputs in all 64 MB a notebook. A message
past a count or the 64 MB is answered `error ID toobig` and changes nothing. A request rhun waits
on that is not answered within 30 seconds fails as above. `nb-output` and `nb-stream` count
against the 16 ms message window like any other message.

### The notebook tab

Jupyter's keyboard. In **edit mode** the selected cell has the keys and every editor command works
in it; Esc goes to command mode (with vim mode on, Esc in vim's normal mode), Shift+Enter runs the
cell and selects the next one (a new one past the last), Ctrl+Enter runs it, Alt+Enter runs it and
inserts a cell below, Up on the first line and Down on the last go to the neighbouring cell. In
**command mode** Enter edits, Up/k and Down/j select, a and b insert a code cell above or below,
d d deletes, z undoes the last cell operation (the last 100 are kept), m and y make the cell
markup or code (its outputs go), Alt+Up and Alt+Down move it, i i interrupts, 0 0 restarts after
asking, o hides or shows its outputs. Every action is also a command named `notebook.*`
(`notebook.run_cell`, `notebook.insert_below`, ...). The toolbar has Run All, Interrupt, Restart,
Clear Outputs and the kernel button; clicking a cell's count column runs it. Save, Save As, Save
All, Revert File, the close and quit questions and the file watcher treat a notebook as one
document: a file changed on disk is read again while the notebook has no changes, else the tab
warns.

When-clause keys: `notebookFocus` (a notebook tab has the keys), `notebookCellEditing` (and its
cell is in edit mode), `notebookCellType` (`code` or `markup`), `notebookKernelState` (the
kernel button's STATE); `activeTab` is `notebook` there. Cells are not reported to extensions'
document events in this revision; the active document is `0` while a notebook tab is active.

Headless controls: `print-notebook` prints a line per cell, `cell=I id=CELL kind=code|markup
lang=LANG lines=N count=C state=none|queued|running|done|failed|cancelled outputs=K sel=0|1
editing=0|1 hidden=0|1 at=X,Y` (`at` the top left of its frame on screen, `-1` off screen), then
`dirty=D mode=edit|command undo=N kstate=S kernel=LABEL`; `notebook=opening` or `notebook=failed
error=TEXT` before it is open; `notebook=none` without one. `print-nb-output I J` prints cell I's
output J: `output kind=K id=OUTID items=TYPE,... show=INDEX lines=N bytes=B keep=K` (with
`image=WxH` once drawn), the text of a text item (ESC as `\e`), then `<eoo>`. `nb-mode
edit|command`, `nb-select I`, `nb-run I` and `nb-output-tab I J` do what the keys and buttons do.
